AI-Enhanced Cholera Surveillance Data Mining

---

AI-enhanced data mining for cholera surveillance data to fill missing observations in WHO African Region historical records through systematic multi-agent search, validation, and integration workflows.


🔗 View Live Dashboard

---

Abstract

This project addresses a critical gap in global cholera surveillance by using the Anthropic Opus 4 LLM to code an advanced agentic AI workflow to systematically mine, validate,

and integrate official and unofficial cholera data sources. With existing surveillance reporting through the WHO AWD Dashboard

and historical reports through the JHU Cholera Taxonomy Repository supplying an initial tranche of data (particularly for later time periods),

our AI data mining focuses on time periods not already represented in these databases. This work directly supports epidemiological modeling in the MOSAIC framework,

which aims to model endemic cholera transmission across the WHO African Region.

Introduction

Problem Statement

Historical cholera surveillance data in the WHO African Region contains substantial gaps, with approximately 50% of weekly surveillance records missing from official databases spanning 1970 to present. These gaps significantly impair epidemiological modeling accuracy, outbreak prediction capabilities, and evidence-based public health planning across 40 MOSAIC framework countries.

Scope and Coverage

Geographic Focus: 40 MOSAIC Framework Countries in the WHO African Region
  • Angola, Burundi, Benin, Burkina Faso, Botswana, Central African Republic, Côte d'Ivoire, Cameroon, Democratic Republic of Congo, Congo, Eritrea, Ethiopia, Gabon, Ghana, Guinea, Gambia, Guinea-Bissau, Equatorial Guinea, Kenya, Liberia, Mali, Mozambique, Mauritania, Malawi, Namibia, Niger, Nigeria, Rwanda, Senegal, Sierra Leone, Somalia, South Sudan, Eswatini, Chad, Togo, Tanzania, Uganda, South Africa, Zambia, Zimbabwe
Temporal Coverage: 1970-present with primary focus on the reporting gaps in each country Data Sources: 486+ pre-authorized domains across 4 reliability tiers

Objectives

  1. Gap Identification: Systematically identify missing surveillance periods across 40 countries
  2. Data Discovery: Deploy AI agents to mine official reports and unofficial cholera data sources
  3. Quality Assurance: Implement rigorous 4-stage validation protocols
  4. Integration: Produce standardized data sets that emulate the formatting of the JHU Cholera Taxonomy Repository with enhanced dual-reference indexing
  5. Documentation: Create comprehensive metadata and with condidence weights for each data source and observation

Methods

Multi-Agent AI Architecture

The methodology employs a systematic 6-agent workflow designed for comprehensive data discovery and validation:

Agent 1: Baseline enhancement and priority source coverage using the "Ultra-Deep Search Protocol" with deep dive modules for WHO DON reports, WHO WER, UNICEF, and MSF \ Agent 2: Geographic expansion around found sources (provincial/district-level data) Agent 3: Zero-transmission validation and absence period documentation with mandatory cross references Agent 4: Obscure source exploration and archive mining Agent 5: Query permutation and expanded search engines Agent 6: Quality audit, validation, formatting checks, and final reporting

Ultra-Deep Search Protocol

  • Multi-engine parallel processing: 15+ search engines/databases per country
  • Query framework: 7 mandatory categories, 50+ unique queries minimum
  • Advanced techniques: Citation following, institution deep-dives, country-specific multi-language searches
  • Source validation: 4-stage quality control with source confidence weighting

Gap-Targeted Intelligence

  • Priority period targeting: Focus on specific missing date ranges
  • Surveillance coverage analysis: Distinguish disease absence vs. reporting gaps
  • Cross-border validation: Regional consistency checks
  • Temporal stratification: Decade-specific systematic coverage

Quality Control Framework

4-Stage Validation Process:
  1. Authentication: URL verification, author credentials, domain validation \
  2. Data Quality: Epidemiological validation (CFR 0.1-15%, attack rates 0.01-10%) \
  3. Cross-Reference: Multi-source confirmation for major outbreaks (>1000 cases) \
  4. Duplication: Systematic detection and resolution protocols \
Source Reliability Classification:
  • Level 1 (0.9-1.0): WHO, MoH, peer-reviewed journals \
  • Level 2 (0.7-0.9): UNICEF, OCHA, established NGOs \
  • Level 3 (0.3-0.6): Reputable news, local government reports \
  • Level 4 (0.1-0.3): Local media, preliminary reports \

Data Standards

Output Format: JHU-compatible CSV with enhanced dual-reference indexing Geographic Coding: AFR::{ISO}::{PROVINCE}::{DISTRICT} standardization Metadata Documentation: 14-column comprehensive source attribution Quality Weighting: 4-tier confidence scoring (0.1-1.0) Data Inclusion Criteria:
  • Geographic specificity: Must represent actual administrative units \
  • Quantitative requirements: Specific case/death counts or validated absence periods \
  • Source authentication: Working URLs, institutional credibility verification \
  • Cholera-specific: Disease incidence data only (not vaccination/capacity metrics) \

Results and Outputs

Angola Pilot Study Results

Quantitative Achievements:
  • Data gap reduction: 454 of 796 weekly records (57%) enhanced \
  • Sources discovered: 25 working URLs across 6 source categories \
  • New observations: 35 data points spanning 1971-2025 \
  • Quality distribution: 60% Level 1-2 sources, 40% Level 3-4 sources \
  • Validation success: 94% of extracted data passed all quality stages \
Key periods filled: Critical gaps in 2006-2012 and 2016-2018 Geographic detail: Provincial-level data added for major outbreaks

Methodology Validation

  • Search comprehensiveness: Multi-engine approach identified sources missed by single-engine searches
  • Quality control effectiveness: Rigorous validation caught and corrected 12% of initial extractions
  • Duplication prevention: Systematic checking prevented inclusion of 8 duplicate records
  • Cross-reference validation: Historical validation identified and resolved 3 data inconsistencies

Data Products

Primary Outputs:
  • cholera_data.csv: Enhanced surveillance data with standardized formatting \
  • metadata.csv: Comprehensive source documentation and validation records \
  • search_report.txt: Summary of discoveries, gaps filled, and quality assessment \
  • Individual agent logs: Detailed search and validation documentation \
Secondary Products:
  • Interactive dashboard: Real-time progress tracking across all countries \
  • Timeline visualizations: Coverage plots showing data enhancement impact \
MOSAIC Framework Integration:
  • Enhanced time series for more complete surveillance records across 40 countries
  • Quality-weighted data observations facilitate the modeling weights built into the likelihood functions

Prerequisites

Required Directory Structure:

``

├── jhu_cholera_data/ # REQUIRED - JHU historical database

├── ees-cholera-mapping/ # REQUIRED - WHO dashboard scraper

└── MOSAIC-data/ # OPTIONAL - Enhanced visualizations

` Clone Required Repositories: `bash

Navigate to your workspace directory

cd /your-workspace/

Clone main repository

git clone https://github.com/InstituteforDiseaseModeling/ai-cholera-data-mining.git

Clone REQUIRED data repositories

git clone https://github.com/InstituteforDiseaseModeling/jhu_cholera_data.git

git clone https://github.com/InstituteforDiseaseModeling/ees-cholera-mapping.git

Clone OPTIONAL visualization repository

git clone https://github.com/InstituteforDiseaseModeling/MOSAIC-data.git # Optional

` Required Python packages: `bash

pip install pandas numpy matplotlib pathlib pillow

`

Automated Setup

`bash

Enter main repository directory

cd ai-cholera-data-mining

Run complete automated setup (handles all initialization)

bash setup.sh

` The setup script automatically:
  1. Repository Dependencies

    2. - ✅ Checks for required adjacent repositories (jhu_cholera_data, ees-cholera-mapping)

    - ✅ Validates data source availability and format compatibility

  1. Baseline Data Integration

    2. - ✅ Integrates JHU cholera database as historical baseline data (1970-2020+)

    - ✅ Integrates WHO dashboard surveillance data from ees-cholera-mapping (2023-2025)

    - ✅ Creates separate baseline files for each country (cholera_data_jhu.csv, cholera_data_who.csv)

  1. Gap Analysis and Targeting

    2. - ✅ Generates integrated baseline gap analysis using combined JHU and WHO data

    - ✅ Creates agent-specific gap targeting files for systematic data collection

    - ✅ Identifies priority periods and missing surveillance coverage

  1. Country Configuration

    2. - ✅ Creates country codes and mappings for 40 MOSAIC framework countries

    - ✅ Creates 40 country directories with separate baseline data files

    - ✅ Generates country-specific workflow prompts from templates

  1. System Setup

    2. - ✅ Sets up dashboard tracking system with enhanced visualizations

    - ✅ Configures reference files and domain authorization lists

    - ✅ Prepares workflow orchestration infrastructure

Required Post-Setup: Agent Configuration

After running setup.sh, you must manually create the specialized agents in Claude Code:
  1. Navigate to agent configuration files:

    2. `bash

    ls ./agents/

    # Shows: agent_0_workflow_orchestrator.md, agent_1_baseline_collector.md, etc.

    `

  1. Create each agent using Claude Code's /agents command:

    2. - Open each .md file in ./agents/ directory

    - Copy the complete system prompt from each file

    - Use /agents command in Claude Code to create each specialized agent

    - Configure the agent with the copied prompt and appropriate tool access

  1. Required agents to create:

    2. - workflow-orchestrator (from agent_0_workflow_orchestrator.md)

    - cholera-baseline-collector (from agent_1_baseline_collector.md)

    - geographic-expansion-specialist (from agent_2_geographic_expansion.md)

    - zero-transmission-validator (from agent_3_zero_transmission.md)

    - obscure-source-explorer (from agent_4_obscure_sources.md)

    - cross-reference-integrator (from agent_5_cross_reference.md)

    - cholera-quality-auditor (from agent_6_quality_auditor.md)

  1. Verify agent creation:

    2. `python

    # Test agent access with Task tool

    Task(description="Test workflow orchestrator",

    prompt="Hello",

    subagent_type="workflow-orchestrator")

    `

⚠️ Important: The workflow will not function until all 7 specialized agents are created in Claude Code using the /agents command.

Workflow Execution

Step 1: Initiate Country-Specific Workflow `bash

Each country has a generated prompt file ready for workflow execution

Location: ./data/{ISO_CODE}/prompt_{ISO_CODE}.txt

Example workflow initiation for Ethiopia:

cat ./data/ETH/prompt_ETH.txt

Copy the entire prompt content and paste into Claude Code command line

The prompt will automatically trigger the workflow-orchestrator subagent

which coordinates all 6 specialized agents sequentially

` Step 2: Monitor Progress and Updates `bash

Update unified dashboard after agent completion

bash update_dashboard.sh

` Step 3: Workflow Pattern for Multiple Countries `bash

For systematic processing of multiple countries:

1. Choose country from list (see ./data)

2. Copy-paste country prompt from ./data/{ISO}/prompt_{ISO}.txt into Claude command line

3. Workflow orchestrator executes all 6 agents automatically

4. Run dashboard update to track completion (also done automatically by each agents)

5. Repeat for next country

`
