ACCESS FINDING - RELIEFWEB'S WEBSITE SEARCH ACCEPTS LUCENE FIELD SYNTAX
--------------------------------------------------------------------------------
The ReliefWeb API still refuses this project: v1 is HTTP 410 decommissioned and
v2 is HTTP 403 "not an approved appname" on both GET and POST. Registration at
apidoc.reliefweb.int needs a human and remains the single highest-value
unblocking action anyone could take for this project.
BUT THE WEBSITE'S OWN SEARCH BOX PASSES ITS QUERY STRAIGHT TO ELASTICSEARCH.
Putting a field range INTO the search parameter works:

  https://reliefweb.int/updates?search=cholera%20Nigeria%20date.created%3A%5B1996-01-01%20TO%202000-12-31%5D

returns results bounded to that window, newest first, paginated with &page=N.
The dedicated UI filters do NOT work headlessly - advanced-search=(PC182) is
silently ignored and sort=date:asc is silently ignored - so the field-range
trick is the only way to reach ReliefWeb's pre-2010 archive without an appname.
THIS SHOULD BE REUSED FOR EVERY OTHER MOSAIC COUNTRY: it opens 1996-2009, which
is the decade this project is thinnest on almost everywhere.

THE 1991 WEEKLY STREAM RESOLVED - ONLY "1.I-" ENTRIES ARE CUMULATIVE
--------------------------------------------------------------------------------
Every Nigeria cholera line printed in WER vol. 66:
  66(21) 24 May : "15.II-14.IV"     values LOST in the scan (blank in OCR)
  66(29) 19 Jul : "...-10.VII"       3 398  /  560     open left bound
  66(32)  9 Aug : "...-23.VII"       3 197  /  331     open left bound
  66(33) 16 Aug : "1.I-6.VIII"      23 463r / 3 116r   CUMULATIVE, revised
  66(38) 20 Sep : "1.I-18.VIII"     48 200r / 6 354r   CUMULATIVE, revised
  66(46) 15 Nov : "1.VIII-30.IX"     6 867  /  750     period increment
THE RULE: an entry is admissible as a national figure ONLY if its left bound is
1.I. The two open-bounded entries (3,398 and 3,197) are partial state returns -
3,197 for a period ending 23 July is LOWER than 3,398 for a period ending
10 July, which is impossible for a cumulative. And 66(46)'s 6,867 for 1 Aug -
30 Sep is flatly contradicted by the cumulatives either side of it (23,463 on
6 Aug, 48,200 on 18 Aug imply ~24,700 in the first eighteen days of August
alone). NONE of the three was entered. This closes the prior pass's open warning
about "a much smaller parallel series": there is no second series, there are
partial returns with open period bounds, and the left bound is the test.
The two cumulatives, with the FMoH figure and the annual, give a four-point
curve whose CFR is stable at 12.9 / 13.3 / 13.2 / 12.9 per cent - the best
internal check available and the reason confidence is 0.9.

THE ADMISSIBILITY RULE THIS BATCH ESTABLISHES, FOR EVERY OTHER MOSAIC COUNTRY
--------------------------------------------------------------------------------
A WER weekly notification entry is usable if and only if BOTH period bounds are
printed. Three sub-cases:
  "1.I-<date>"      -> a year-to-date CUMULATIVE. Enter as TL=1 Jan.
  "<date>-<date>"   -> a TRUE PERIOD INCREMENT. Enter as printed.
  "...-<date>"      -> UNUSABLE. The ellipsis is WER's own "data not yet
                       received" mark; the entry is a partial return whose
                       start is unknown, and treating it as a cumulative
                       understates the country badly.

1. IRIS [full issue] PDFs of the WHO Weekly Epidemiological Record.
   Search title:"<year>, vol. <v>" in the DSpace discover endpoint; 46-51 full
   issues per volume; a whole volume harvests in about 90 seconds.
   **The IRIS API returns 403 to a browser User-Agent and 200 to curl's
   default.** That is the inverse of ReliefWeb's rule and will silently cost an
   agent the whole archive if it carries one UA for the session.
   THE ADMISSIBILITY RULE: a WER notification entry is usable only if BOTH
   period bounds are printed. "1.I-<date>" is a year-to-date cumulative;
   "<date>-<date>" is a true increment; "...-<date>" is UNUSABLE, because the
   ellipsis is WER's own "data not yet received" mark.
   ALWAYS CHECK THE DISEASE HEADING. Nigeria appears under YELLOW FEVER in the
   same table block in WER 1992;67(47) and 2000;75(21); a "Nigeria near
   numbers" grep would have fabricated cholera rows from both.
   FOR WIDE TABLES, RENDER THE PAGE. pdftotext -layout interleaves adjacent
   rows and adjacent disease blocks. Three figures in this run were settled by
   pdftoppm -r 200 and reading the image, and one of them (WER 1996;71(16))
   turned "probably an OCR error" into a documented WHO-internal conflict.
