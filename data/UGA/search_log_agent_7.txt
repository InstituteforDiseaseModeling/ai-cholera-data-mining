    late 2023-2024 with blank sCh that py/build_weekly_timeseries.py zero-fills
    into unlabelled absences. The file does carry 74 such national weekly rows,
    spanning 2023-07-31 to 2025-03-23. But the builder no longer zero-fills them.
    load_national_rows() sets has_count=False for a blank sCh, and BOTH
    downstream loops skip such rows outright:
      weekly loop      "if not r['has_count']: continue   # blank sCh = no count
                        reported; not an observation"
      non-weekly loop  "if not r['has_count']: continue   # blank sCh = no count

    Empirically confirmed against the existing ./data/UGA/cholera_weekly_UGA.csv:

    NO ACTION NEEDED, and a future run should not spend effort on it.

D2. A REAL BUILDER DEFECT FOUND WHILE CHECKING D1 - ROWS WITH A COUNT BUT NO
    sCh ARE SILENTLY DISCARDED.
    has_count is keyed on sCh ALONE, so a row carrying only cCh, or only deaths,
    is dropped rather than used. Scanned all three UGA layers for national rows
    with a blank sCh but a non-blank cCh or deaths:
      AI  row 197  2023-01-01..2023-12-31  cCh 65   <-- MATERIAL LOSS
      AI  row 198  2015-01-01..2015-12-31  cCh 137
      AI  row 199  2018-01-01..2018-12-31  cCh 109
      JHU row 1314 2018-04-09..2018-04-18  deaths 0
      JHU row 1479 2018-02-11..2018-04-24  deaths 44
    The 2023 loss is the serious one. WHO's own annual states that Uganda "did
    not report cholera data to WHO for 2023", so row 197 is the ONLY national
    figure for that year anywhere - 65 culture-confirmed cases from Uganda's
    National Microbiology Reference Laboratory - and MOSAIC currently receives
    nothing for it. Suggested fix, for the pipeline owner and not for a country
    agent: treat a row as informative when ANY of sCh, cCh or deaths is present,
    and disaggregate on whichever is available. NOT FIXED HERE - py/ is outside
    this agent's write scope.

D3. THE JHU 404 DIAGNOSIS IN MY BRIEF IS WRONG, AND THE CORRECT ONE MATTERS.
    All 55 URLs in ./data/UGA/metadata_jhu.csv do return HTTP 404. But the stated
    cause - ".csv stripped, UID truncated to 3 digits" - is not what the file
    contains. Every URL ends in a full "ObservationCollectionNNNNN.csv"
    (e.g. .../ObservationCollection4903.csv, .../ObservationCollection20872.csv,
    .../ObservationCollection20944.csv), and I matched all 55 filenames against

    locally, zero mismatches. They 404 because
    github.com/InstituteforDiseaseModeling/jhu_cholera_data is a PRIVATE
    repository - the repository ROOT returns 404 to anonymous HTTP too (F12).
    Nothing is malformed and no data is lost; the citations are simply not
    publicly resolvable. A future agent told to "fix the truncated UIDs" would
    find nothing to fix and might mangle working URLs trying.

D4. JHU APPARENT DUPLICATION FOR 1999 AND 2000. ./data/UGA/cholera_data_jhu.csv
    sums to 10,234 cases / 458 deaths for 1999 and 6,131 / 341 for 2000, against
    WHO's official 5,179 / 228 and 2,807 / 172 - almost exactly double in both
    years (Agent 3 finding F30). Separately, JHU renders the Moroto 2010 outbreak
    four times over. DO NOT TREAT JHU SUB-NATIONAL SUMS AS AN INDEPENDENT
    RECONSTRUCTION FOR ANY UGANDAN YEAR.

D5. THE JHU 2022 NATIONAL ZERO, LEFT STANDING. Defensible on Agent 6's analysis
